### Technical Details
- **URL scheme**: `CFBundleURLTypes` added to `SleepGuard/Info.plist` (scheme `sleepguard`, name `com.dardan.SleepGuard`). Merged with the generated Info.plist keys.
- **Entry**: `SleepGuardApp` `.onOpenURL` parses with `WidgetDeepLink(url:)` and ignores the link until onboarding is complete.
- **Hand-off**: `TabCoordinator.pendingDeepLink` + `open(_:)` (Env). `open` ignores the link if remote config hides the Statistics tab; otherwise it selects that tab and stores the link.
- **Consumption**: `StatisticsTab.routePendingDeepLink()` runs on `onAppear` (cold launch, when the URL arrives before the tab mounts) and on `onChange(of: tabCoordinator.pendingDeepLink)` (warm). It clears the link first, then drops it while recording or while a sheet is presented.
- **Routing**: `SleepGuard/DeepLinkRouter.swift` pops to root, then pushes `.liveSession` / `.sessionDetail(id:)` / `.last7Nights`. Before pushing a session it checks that the session exists (`fetchCount` with an `id` predicate, `fetchLimit = 1`). If the session is gone, it stays on the dashboard.

### Architecture Decisions
- **Statistics tab owns deep links**: it already owns the start → live session → summary sheet flow, and every route the widgets need is in `withAppRouter`. Routing through one tab keeps a single consumer of `pendingDeepLink`.
- **Drop, don't queue, while busy**: replaying a link after recording or a summary sheet would surprise the user. Dropping it just opens the app where they are.
- **Router helper in a separate file**: keeps `StatisticsTab` at ~175 lines (limit 200) and the route table in one place.
- **No fallback tab when Statistics is hidden**: the Sessions tab can't present the start/summary flow, so a partial fallback would be worse than opening the app.
